# 阶段上下文与结构化经历

> 覆盖 0.4.0 – 0.6.0。标题原为「0.4.3」，内容已随版本追加，不再以单一版本命名。

## 上下文入口

`src/core/context.ts` 提供三个上下文构建函数，Host 不再向模型直接发送完整 `world` 或完整世界资料。

| 阶段 | 默认数据 |
| --- | --- |
| `buildActionContext` | 玩家输入及现场、玩家属性/技能/背包、当前位置与路线、在场或被提及人物的公开身份、当地/持有商品、相关任务和提议、当前调查与玩家知情经历 |
| `buildNpcContext` | 当前人物资料、自有资源、关系、最近知识和对话、其知情经历（包含已结算的最近经历）、自己的提议、委托概要；不传玩家私有背包、其他 NPC 私有历史或真实未汇报任务进度 |
| `buildSceneContext` | 当前玩家可见场景、可用行动依据、已提交行动摘要和单一经历列表、人物已提交的台词；不再传 currentEvents 或 previousScene |

地点现有 `description` 作为公开环境，人物 `profile` 只进入对应 NPC 上下文。既有地点登记仍沿用原规则，不在本次重做地图发现机制。规则引擎继续读取完整状态，模型上下文裁剪不改变规则校验范围。

默认最多带最近 30 条相关知情经历、10 条当前地点调查、NPC 自己最近 20 条旧知识和 12 条旧对话。没有实现自动摘要；原记录不删除。`tg_read_context` 可选 `query` 参数，以关键词或实体编号查找较早经历，每次最多返回最近 30 条匹配并报告匹配数。查询先过滤知情者，再匹配；NPC 查询不能通过换关键词切换身份。省略参数返回原阶段上下文。

## 经历写入

`world.memories` 为可选字段，旧存档仍可读取，不推测补造历史知情关系。记录包括 `id/kind/text/minute/locationId/actionId/generation/speakerId/knownBy/relatedNpcIds/relatedItemIds/relatedQuestIds`。

- `applyPlan` 在世界副本中执行步骤，记录观察、行动结果与玩家说过的话。时间使用所在行动组结束时间，地点保留该步骤执行地点。
- 普通私人行动只赋予玩家知情权；交谈、汇报、交付、处理提议和初次结识只赋予玩家及直接互动 NPC。不自动把在场第三者算作见证人。
- 交付事实与附带说明分别记录。`dialogue` 证明说过这些话，不证明话中所述事情真实发生。
- `applyReply` 校验全部回应与提议后，在副本中记录人物台词、参与者和提议关联对象。礼物/委托仍需另行接受。
- 编号、时间、关联与知情者由程序填写；模型结果结构没有 `knownBy` 或任意经历写入接口。
- 两个函数不直接持久化，工具预校验仅操作副本；`GameService` 把经历与状态一次提交。失败丢弃副本，重复请求与阶段重试沿用既有提交保护。

旧 `knowledge/history/facts/events` 字段暂时保留以兼容规则、存档与现有界面；模型不再读取完整事件日志。存档校验新增经历编号唯一性、知情人物及关联地点/物品/任务的有效性检查。

## 0.4.2 上下文与提交协议

经历只通过 memories 列表提供，包含已结算的最近记录；NPC 不再重复传 trigger。currentActionId 仅用于定位本轮记录，actionResult 保留结算摘要（包括耗时或无效果原因），不表示重复执行。

三个阶段均提供 time.label（游戏第几天及24小时制时间）和 time.period（时段），保留累计绝对分钟 minute。时段按小时划分：0–4 凌晨、5–7 清晨、8–11 上午、12–13 中午、14–17 下午、18–19 傍晚、20–23 夜间；这是游戏叙事约定，不计算真实日出日落。提示词要求当前时间优先于地点静态氛围。

所有阶段明确要求调用 tg_propose_result，将结果序列化为 json 字符串参数；普通文本中的 JSON 不算提交，收到 STAGED 后才能结束。未增加普通文本自动结算后门。

## 0.4.3 阶段提示词与消息布局

- `src/host/prompts/plan.ts`：理解行动的完整规则、结果格式及上下文段落。系统消息包含环境、时间、当前展示、行动依据和知情经历；用户消息仅为玩家本次输入。
- `src/host/prompts/reply.ts`：NPC 的完整规则、结果格式及上下文段落。系统消息包含人物资料、环境和知情历史；用户消息包含按 currentActionId 筛出的本轮知情互动。结构化经历按行动编号拆分，两侧不重复传递，不把玩家原始输入或私有经历送给 NPC。
- `src/host/prompts/scene.ts`：现场生成的完整规则、结果格式及上下文段落。系统消息包含时间、地点、可见状态、结算摘要和经历；用户消息只是生成请求。
- `src/host/prompts/index.ts`：按阶段选择模板，返回 `{system,user}`。`format.ts` 仅提供类型和资料格式化，不包含共享的行为提示词。
- `src/host/model.ts`：选择裁剪后的阶段上下文，注册模板生成的系统消息，发送模板生成的用户消息；工具校验、结算和调用上限不变。

每个模板独立维护完整指令，必要的工具协议和时间约定在各模板中明确保留。资料以带标记的 JSON 段落插入；模板明确它们不是指令，并转义尖括号，防止资料关闭边界标记。这是输入分隔措施，不承诺模型能完全抵御提示注入。玩家本次自由输入不提升为系统指令。

`tg_read_context` 保留按需读取裁剪上下文的能力；默认初始消息不再同时在 system/user 中复制整份上下文，模型主动查询时仍可读回资料。调用记录沿用宿主原始消息与工具记录，无需改变存储格式。

## 0.4.4 自然语言插值

现场资料从 JSON 对象改为模板字符串插值：现在是具体日期与钟点（时段），天气为当前天气，玩家或 NPC 在具体地点。NPC 另直接插入姓名、人物编号、设定、关系、已有知识和过往对话；不再额外复制完整 npc/place 对象。任务、物品、资源及结构化经历仍保留准确字段和编号。format.ts 的 literal 只处理插入值的换行和引号，不递归解释变量；proseSection 保留游戏资料边界并转义尖括号。

## 0.5.0 外部模板

实际可编辑模板移至 DSH_HOME/tg/prompts（默认 ~/.dsh/tg/prompts）。每阶段调用前读取 system/user 两文件并一次替换变量；独立阶段变量仍由裁剪后的上下文构建。默认文字集中在 src/host/prompts/defaults.json。模板错误回退到本次运行中最近有效版本，首次无有效版本时回退内置默认，并在调用记录的 promptWarning 中显示原因。升级不覆盖现有模板。完整变量表及错误处理见插件 README 的 0.5.0 节。

46 项测试通过，覆盖连续修改、调用快照不变、未知变量、空文件、修复恢复、重启不覆盖用户文件及原有规则回归。

## 0.6.0 独立对话（2026-10-26）

游戏记录新增可选 dialogue（npcId、locationId），旧存档不含该字段时仍为正常模式。选择当前生成选项后，plan 阶段允许模型调用 tg_enter_dialogue；工具只暂存模式提议，GameService 校验并保存，进入本身不耗时、不代替玩家说话。纯交谈选项通过旧 talk 提议时会得到工具纠正提示。

聊天消息直接按 1 分钟说话行动结算并记录经历，再调用 reply；不会再调用 plan 或 scene。对话界面按 speakerId 展示玩家与当前人物的知情对白。失败/取消后的重试只补齐 reply，不重扣时间、不重复追加玩家经历。消息中的移动、交付等文字只是对白，实际行动须退出后在现场操作。

退出通过 exitDialogue 请求清除模式，取消旧请求，单独执行 scene 一次。若退出保存失败，原 NPC 调用继续；保存成功后迟到回复不可提交。现场生成失败可独立重试。发送和退出均校验请求编号与状态版本，持久化沿用原有自动保存、手动存档和恢复机制。

外部提示词文件保留。选项的交谈工具协议、独立聊天的对白边界附加为运行协议；其最终文本与 tg_enter_dialogue 的实际工具调用仍记录在原生轨迹。
