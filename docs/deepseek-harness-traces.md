# 游戏调用轨迹

插件在“文字游戏 → 调用记录”中按玩家行动分组，阶段内采用接近 Harness 0.2.1-rc.2 轨迹的布局：事件时间轴、事件表格、右侧详情。支持搜索、显示全部事件、正文与原始 JSON 切换；工具调用按 callId 与结果关联，显示实际时间戳计算的耗时。缺失时间和 usage 不估算。下文按版本记录变更。

这是 TG 自己的只读展示组件，并非直接嵌入 DSH 的轨迹组件。本机官方 `dsh-client-ui-trajectory` 只导出插件入口，内部视图依赖普通会话服务。TG 保留自己的行动与阶段分组，避免为查看记录恢复或运行普通会话。没有实现官方视图的所有功能，例如时间轴缩放、虚拟滚动和请求上下文差异比较。

模型事件由 Harness 原生会话持久化保存。插件在 `tg_traces_v1` 域保存游戏、行动、运行代次、阶段与 sessionId 的关联；运行时读取活跃快照，结束后通过 `sessionPersistence.open(id, "read")` 分页读取并关闭句柄。只允许读取已关联到当前游戏的会话。旧行动不猜测补关联，日志缺失明确显示错误。

实际结算保存在游戏记录的 `settlements` 字段中，与世界状态同一次写入。模型的 STAGED 工具结果只表示提议通过校验。读档保留本机结算历史并追加恢复标记；模型提示词不包含轨迹。原始事件和实际结算可以导出为选中行动的 JSON 快照。
